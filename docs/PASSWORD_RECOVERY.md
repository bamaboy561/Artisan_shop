# Восстановление пароля

Вход → «Забыли пароль?» → email аккаунта → одноразовая ссылка → новый пароль и подтверждение → обычный вход.

Ссылка действует 30 минут. Повторный запрос заменяет предыдущую ссылку. Максимум 5 запросов на email в сутки UTC, интервал 60 секунд; общий лимит 1000 запросов в сутки. Ответ одинаковый для существующих и неизвестных аккаунтов. Отправка выполняется через Next.js `after`, без ожидания почтового провайдера в ответе формы.

Настройки Production в Vercel:

- `RESEND_API_KEY`: ключ Resend.
- `AUTH_EMAIL_FROM`: подтверждённый отправитель Resend, например `Artisan <no-reply@artisan.shop.kg>` только после подтверждения домена.
- `DATABASE_URL`, `SESSION_SECRET`: существующие настройки авторизации.

После изменения настроек нужен новый деплой. Без почтовых настроек форма честно показывает недоступность восстановления и телефон магазина. Отправка не считается подтверждённой фактической доставкой: при проблемах проверить Resend delivery events, в том числе spam/bounce.

В базе хранится только SHA-256 ссылки. Используется существующая таблица `SiteSetting`: по одной записи восстановления и отзыва сеансов на аккаунт, лимиты по хешу email. Миграция схемы не требуется. Просроченная запись перезаписывается новым запросом. Смена пароля и потребление ссылки выполняются одной транзакцией, повторное или одновременное использование не допускается. Изменившиеся email/пароль и заблокированные аккаунты не принимают ранее выданные ссылки.

После смены пароля прежние сеансы становятся недействительными, включая JWT старого формата; новые сеансы работают как прежде. Клиент получает отдельное письмо о смене пароля, без самого пароля. Ошибка этого уведомления не отменяет уже выполненную смену. Заказы, бонусы, роли и Telegram не изменяются. Новый пароль: минимум 8 символов, максимум 72 байта UTF-8 (ограничение bcrypt без тихого усечения).

Адрес в письме всегда `https://artisan.shop.kg`, не берётся из заголовка Host. Страницы закрыты от индексации и используют `no-referrer`.

Проверка: `npx tsx --test tests/password-recovery.test.mjs`. Тесты используют изолированные заглушки базы/почты и реальное хеширование bcrypt. Для запуска нужна отдельная проверка доставки реального письма на тестовый аккаунт после настройки отправителя; локальные тесты её не заменяют.
